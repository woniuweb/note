1. 多线程的运行的方式流程
线程生命周期（运行流程）
新建 NEW：new Thread ()，创建对象，未启动
就绪 RUNNABLE：调用 start ()，进入就绪队列，等待 CPU 调度
运行 RUNNING：CPU 分配时间片，执行 run () 方法
阻塞 BLOCKED：
等待锁、sleep、wait、IO 操作，让出 CPU
终止 TERMINATED：run 执行完 / 异常退出，线程结束

2. 线程池的执行流程
当调用 execute() 提交一个任务时，线程池执行顺序：
1）先判断核心线程数是否满了
没满 → 创建核心线程执行任务。
2）核心线程已满 → 判断阻塞队列是否满了
队列没满 → 任务放进任务队列，等待空闲核心线程执行。
3）队列也满了 → 判断最大线程数是否满了
没满 → 创建 ** 非核心线程（临时工）** 执行任务。
4）最大线程数也满了 → 触发拒绝策略
拒绝执行任务。

4种拒绝策略：1. AbortPolicy，默认抛异常；2. CallerRunsPolicy，主线程自己执行；3. DiscardPolicy，静默丢弃；4. DiscardOldestPolicy，丢弃队列最老任务，再放新任务。

4. redis哨兵模式了解吗
一句话定位：哨兵（Sentinel）是 Redis 的高可用方案，监控主从，自动故障转移。
工作流程（背这个）
哨兵监控主节点 + 所有从节点，心跳检测是否存活
主节点挂了，哨兵内部投票（半数以上同意），确认客观下线
自动从从库中选一个新主节点
其他从节点自动切换，复制新主
客户端自动切换连接新主
作用
监控
自动故障转移
通知客户端
缺点：不能负载均衡，只能主从读写分离，高可用。

5. mysql的索引原理是什么？b+树？为啥是b+树
4.1 索引原理
MySQL InnoDB 索引是B + 树结构，索引存在磁盘上。查询时先通过索引快速定位数据页，减少磁盘 IO，提高查询速度。主键索引叶子节点存整行数据，二级索引叶子节点存主键 ID。
4.2 什么是 B + 树
多路平衡查找树
所有数据都在叶子节点
叶子节点用双向链表串联，有序
非叶子节点只存索引 key，不存数据
4.3 为什么用 B + 树，不用 B 树、红黑树？（重点！直接背）
B + 树非叶子节点更小，IO 更少B 树每个节点存 key + 数据，节点大；B + 树非叶子只存 key，一页能存更多索引，树更矮，磁盘 IO 次数更少。
范围查询极强B + 树叶子节点是链表，连续有序，> < between like 直接遍历链表；B 树要多次遍历。
查询效率稳定B + 树所有查询都要走到叶子节点，IO 次数一致；B 树深度不同，效率不稳定。
比红黑树好红黑树是二叉树，树太高，IO 次数多，不适合磁盘存储；B + 树是多路，深度极低。
4.4 面试精简版回答（直接说）
MySQL InnoDB 用 B + 树做索引。B + 树所有数据在叶子节点，叶子节点有序链表，非叶子节点只存索引，节点更小，IO 更少。同时范围查询特别友好，比 B 树和红黑树更适合磁盘存储，所以用 B + 树。
